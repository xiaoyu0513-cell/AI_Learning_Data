# 本次改进：实现与调试

以下功能已接入现有项目。旧版图谱节点和原向量集合保留，新版本使用独立命名空间。

## 在 VS Code 中按这条路径阅读

1. `backend/main.py`：`lifespan` 自动恢复活动版本；`/api/chat` 校验输入并输出 SSE；构建、图谱和规则工具移出事件循环。
2. `backend/system.py`：`build` 读取数据、比较内容哈希、构建新索引、校验数量、最后发布版本。`restore` 恢复，`rollback` 回滚。每轮问答捕获同一个快照，避免混用新旧检索器。
3. `backend/rag_modules/index_store.py`：SQLite 保存版本、活动指针和向量缓存；文件锁排除第二个构建进程。更新时只对内容发生变化的文档重新编码，但会创建完整的新 Milvus 集合和 Neo4j 投影。
4. `backend/rag_modules/graph_snapshot.py`：版本化 `RAGEntity` 节点和白名单关系；岗位使用种子文件中的 `nodeId` 作为稳定业务 ID，不用岗位名称作主键。
5. `backend/rag_modules/query.py` → `hybrid_retrieval.py` → `reranker.py`：规则解析城市、公司、职级和技能别名；技能取交集；先筛选再召回，RRF 融合后由可选 CrossEncoder 重排。
6. `backend/rag_modules/graph_rag_retrieval.py`：岗位→技能、岗位→公司及最多三跳技能前置路径。证据保留关系类型和方向，使用有界参数化模板，不执行模型生成的 Cypher。
7. `backend/services/chat_service.py` → `workflow.py`：LangGraph 的 parse → retrieve → rerank → gap → generate；有界异步事件队列输出 SSE；SQLite 检查点记录完成的历史及上轮岗位 ID。
8. `backend/rag_modules/llm.py`：AsyncOpenAI、请求超时、有限重试、流关闭及 token usage。`services/observability.py` 记录阶段耗时、路由、降级及错误类型，可选发送 Langfuse 元数据。
9. `backend/evaluation/run.py` → `backend/tests`：真实检索指标和回归测试。前端评测页面读取报告；Gap 页面从活动版本读取候选人、岗位和实际公司信息。

推荐断点：`system.build` 的 `store.publish` 前、`workflow.retrieve` 的路由调用后、`workflow.generate` 写入历史前。运行项目根目录的 `python -m pytest -q` 可先理解不依赖数据库的路径。

## 数据更新与回滚

修改 `backend/data/seed/jobs.json`，保留岗位原有 `nodeId`；改名、技能变化和下架均通过重新构建发布。岗位全部清空暂不允许发布。

`POST /api/admin/build`，JSON：`{"force":false}`。数据不变时复用；有变化时返回 added/updated/deleted 的岗位 ID。`force=true` 创建新版本，不删除当前服务集合；已缓存的相同文本向量仍会复用。

只有新版本图谱、向量数量及 BM25 初始化通过后，才更新 SQLite 活动指针。构建失败会记录 failed 并保留旧版本。它是单机发布协议，**不是跨 Neo4j/Milvus 的分布式事务**。

`GET /api/admin/versions` 查看已发布版本，`POST /api/admin/rollback` 携带 `{"version":"从列表复制的32位版本号"}` 可在验证外部资源存在后切换。回滚不改写种子 JSON，后续再次构建会以 JSON 为准。Embedding/schema 配置不兼容的旧版本不能直接加载。

旧版本、失败构建残留和向量缓存暂不自动清理，防止删除仍在使用的资源；多次构建会增长磁盘与内存占用。当前按 **单进程、单 Uvicorn worker** 使用，跨进程会话互斥与活动版本同步尚未实现。

## 会话、约束与故障行为

- 前端在 sessionStorage 保存随机 session ID，刷新同一标签页后可延续服务端会话；聊天记录 UI 本身暂不回显历史。关闭标签页后可创建新会话。
- 追问“这些里面”“第二个岗位”等会限定上轮返回 ID；支持前三个序号。索引版本发生变化时拒绝沿用旧序号，请重新检索。
- 只有成功完成的回答写入对话历史；超时、取消和上游错误不提交半截回答。检查点仍可能保留本轮中间检索状态。
- 图谱失败或空结果会尝试混合检索，向量失败继续 BM25；返回证据包含降级原因。模型失败直接返回 error，不把检索片段冒充生成答案。
- 城市、公司、职级和技能解析是规则实现，存在词表、否定、范围和“或”关系理解局限。复杂条件可通过 `/api/chat` 的 `filters` 显式传入；它覆盖同名自动解析字段。技能筛选包括必需与加分项，Gap 的分母仅包含必需技能。
- 整体请求及检索阶段有超时；断开 SSE 会取消异步模型流。已进入线程的同步模型推理或数据库调用无法被 Python 强行中止，依赖驱动超时或计算结束退出。
- 上下文按字符预算截取完整证据并重新编号，检查无效引用编号；这不等价于事实核验或防止所有幻觉。当前没有语义置信度拒答阈值。

请求示例：

```json
{"query":"同时会 Go 和 k8s，在杭州有什么岗位", "top_k":5,
 "session_id":"example_session_20261111",
 "enable_agentic":true,
 "filters":{"location":"杭州","skills":["Go","Kubernetes"]}}
```

## 启用重排序

已接入 `sentence_transformers.CrossEncoder`，默认关闭，避免启动时额外下载大模型。启用前在项目虚拟环境下载：

```powershell
$env:HF_HUB_OFFLINE = "0"
$env:TRANSFORMERS_OFFLINE = "0"
& ./.venv/Scripts/python.exe -c "from huggingface_hub import snapshot_download; snapshot_download('BAAI/bge-reranker-base')"
```

在 `backend/.env` 设置 `RERANK_ENABLED=true` 后重启后端。模型只从本地缓存加载；失败时返回 `rerank_status=unavailable`，保留融合顺序。日志会给出加载错误。重排序分数不是概率，前端按原始分数显示。

本轮验证了真实 BGE 向量检索、CrossEncoder 的接口和失败分支；**没有下载或运行真实 CrossEncoder，也没有声称它提高了准确率**。启用后用 full 评测验证。

## 可观测性

默认写 `backend/runtime/traces.jsonl`，记录 request_id、版本、阶段耗时、结果数量、降级、错误类型和服务端实际返回的 token usage，不写问题和答案正文。SQLite 会话检查点会保存本地问答和检索文本，runtime 已加入忽略列表。

Langfuse 使用已安装的 Python SDK 3.x。设置 `LANGFUSE_ENABLED=true`、`LANGFUSE_HOST`、`LANGFUSE_PUBLIC_KEY`、`LANGFUSE_SECRET_KEY` 并重启。只上传阶段元数据；相同 request_id 关联同一 trace。适配器已用替身客户端测试；未连接真实 Langfuse 服务。默认地址只是配置示例，项目没有新增 Langfuse Docker 服务。

## 评测与测试

```powershell
& ./.venv/Scripts/python.exe -m pytest -q
# Docker 数据库已启动，并缓存 BGE 模型时，额外验证真实集成：
& ./.venv/Scripts/python.exe -m pytest -q --run-integration
& ./.venv/Scripts/python.exe backend/evaluation/run.py --mode offline
& ./.venv/Scripts/python.exe backend/evaluation/run.py --mode full
```

offline 只跑 BM25；full 比较 BM25、向量、混合、图谱及启用后的 rerank。未启用方案显示 skipped，失败方案显示 partial_failure。报告保存到 `backend/runtime/evaluation.json`，页面访问 `/evaluate` 查看。

指标包括 Recall@K、MRR、Hit@K、空答案拒答率、结构化条件满足率、条件抽取准确率和检索 P50/P95；包含版本、数据/标注哈希、逐题结果及降级记录。无答案题不计入 Recall/MRR。评测不调用 LLM，不报告答案准确率、幻觉率或虚构费用。

现有 32 题基于 20 条种子岗位，强约束题较多，属于回归冒烟集，不能证明泛化能力或重排序收益。继续扩展独立语义改写题、难负例和人工答案标注后，再用于简历中的效果指标。

GitHub Actions 在 push/PR 后执行离线回归、保存评测报告并构建前端；没有自动启动数据库或调用付费模型。CI 配置已写入，但需要提交推送后才会在 GitHub 实际运行。

公开部署还需实现认证、会话所有者校验、管理接口权限、数据生命周期与生产监控；当前按本地开发项目运行。
